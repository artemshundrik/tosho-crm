# Захоплення задач із Claude Cowork

Ендпоінт, через який задача потрапляє на дошку «Запити» ззовні CRM: надиктував
фразу в Cowork або кинув скріншот — картка вже на дошці, з назвою, типом,
напрямком і пріоритетом.

- Код: [`netlify/functions/dev-request-capture.ts`](../netlify/functions/dev-request-capture.ts)
- Чиста логіка + тести: [`netlify/functions/_lib/devRequestCapture.ts`](../netlify/functions/_lib/devRequestCapture.ts)
- Адреса: `POST https://tosho.pro/.netlify/functions/dev-request-capture`

Розбір тексту — той самий, що у вікні «Новий запит» і в Telegram-боті
([`_lib/devRequestDraft.ts`](../netlify/functions/_lib/devRequestDraft.ts)), тож
картки з усіх трьох входів виглядають однаково.

**Користувач рівно один — власник.** Ні таблиці ключів, ні прив'язки токена до
людини немає й не планується: і секрет, і uuid автора приходять з оточення
Netlify. Токен дає право лише **писати** картки від імені цієї однієї людини —
прочитати ним не можна нічого. Тобто витік коштує спаму на дошці, а не даних.

---

## 1. Налаштувати (одноразово)

Треба дві змінні оточення в Netlify. Поки бодай однієї немає, ендпоінт відповідає
`503` і не робить нічого — ні розбору, ні запису.

### 1.1. Згенерувати токен

```sh
openssl rand -hex 32
```

Скопіюй результат. Це і є `DEV_REQUEST_CAPTURE_TOKEN` — більше він ніде не
зберігається, тож поклади його одразу в 1Password.

### 1.2. Дізнатись свій uuid

Через psql (той самий доступ, що для міграцій):

```sh
set -a && . ./.env.backup && set +a
psql "$BACKUP_DB_URL" -c "select id, email from auth.users where email = 'artemshundrik@gmail.com';"
```

Без термінала: Supabase → Authentication → Users → знайти себе за поштою,
скопіювати `UID`.

### 1.3. Покласти в Netlify

Netlify → Site configuration → Environment variables → **Add a variable**, для
кожної:

| Змінна | Значення | Scope |
| --- | --- | --- |
| `DEV_REQUEST_CAPTURE_TOKEN` | те, що видав `openssl` | **Functions** |
| `DEV_REQUEST_CAPTURE_USER_ID` | uuid із кроку 1.2 | **Functions** |

Scope навмисно лише `Functions`: у збірці ці значення не потрібні, а все, що
потрапляє в `Builds`, має шанс осісти у клієнтському бандлі.

**Змінні починають діяти лише з наступного деплою.** Деплой коштує ~15 кредитів
([`DEPLOY_POLICY.md`](DEPLOY_POLICY.md)), тож ставити їх варто **до** того, як
викочувати пачку комітів — тоді один деплой закриває і код, і налаштування.

## 2. Перевірити, що живий

Спершу без токена — має бути `401`:

```sh
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  https://tosho.pro/.netlify/functions/dev-request-capture \
  -H 'Content-Type: application/json' \
  -d '{"text":"перевірка доступу"}'
```

> `503` замість `401` означає, що змінні ще не доїхали: або їх немає, або після
> їх додавання не було деплою.

Тепер із токеном — має з'явитись картка:

```sh
curl -s -X POST https://tosho.pro/.netlify/functions/dev-request-capture \
  -H 'Content-Type: application/json' \
  -H "x-capture-token: ТУТ_ТОКЕН" \
  -d '{"text":"Перевірка захоплення з Cowork: у списку прорахунків не видно, хто останній редагував"}'
```

Відповідь:

```json
{
  "ok": true,
  "number": "REQ-42",
  "title": "У списку прорахунків не видно, хто останній редагував",
  "kind": "Незручно",
  "module": "Прорахунки",
  "priority": "Звичайний",
  "url": "https://tosho.pro/dev-requests",
  "message": "📝 REQ-42 — записав\nУ списку прорахунків не видно, хто останній редагував\nНезручно · Прорахунки · Звичайний\nhttps://tosho.pro/dev-requests"
}
```

Картка лягає в колонку **«Вхідні»** (`triage`) — це захоплення на бігу,
а не свідоме заведення з дошки, тож її ще має побачити людина.

Перевірочну картку потім прибери з дошки руками.

### Що означають коди

| Код | Що сталось |
| --- | --- |
| `200` | Записано. Дивись `message`. |
| `200` + `"duplicate": true` | Номер уже зайнятий (гонка лічильника). Повтори запит — візьме наступний. |
| `400` | Порожній або закороткий текст (треба хоча б 3 символи), чи тіло не JSON. |
| `401` | Токен не збігся або заголовка немає. |
| `503` | Змінні оточення не налаштовані. |

Поле `existingFeature` з'являється, лише коли розбір упізнав уже наявну
можливість CRM («схоже, це вже працює: …»). Картку це не скасовує.

Якщо модель не відповіла, картка все одно створюється — з сирим текстом і
типовими значеннями, а в `message` буде рядок «Розбір не спрацював».

## 3. Скіл для Cowork

Збережи як `SKILL.md` у теці скілів Cowork (наприклад
`~/.claude/skills/tosho-capture/SKILL.md`).

**Токен у файл не вписуй.** Скіл читає його зі змінної оточення — додай у
`~/.zshrc` рядок `export TOSHO_CAPTURE_TOKEN='…'` і перезапусти термінал. Так
файл скіла лишається звичайним текстом, який не страшно кудись покласти.

````markdown
---
name: tosho-capture
description: Заводить задачу на дошку «Запити» в Tosho CRM. Використовуй, коли просять «заведи задачу», «додай у беклог», «запиши в запити», «закинь на дошку», «створи задачу в CRM», «запиши, щоб не забути» — або коли надиктували чи прислали скріншот із проблемою в CRM і треба це зафіксувати.
---

# Завести задачу в Tosho CRM

Надсилає текст задачі на ендпоінт захоплення. CRM сама складе назву, визначить
тип (не працює / незручно / нова можливість), напрямок і пріоритет.

## Як діяти

1. **Збери текст задачі.**
   - Надиктували голосом — бери розшифровку як є, разом із подробицями.
   - Прислали скріншот — розпізнай, що на ньому, і опиши проблему словами:
     що видно, де саме в CRM це видно, що не так.
   - Нічого не вигадуй і не додавай від себе: порожній опис кращий за
     придуманий. Назву й класифікацію складе CRM, твоя робота — передати суть.

2. **Надішли.** Заміни `ТЕКСТ ЗАДАЧІ` на зібраний текст:

   ```bash
   curl -s -X POST https://tosho.pro/.netlify/functions/dev-request-capture \
     -H 'Content-Type: application/json' \
     -H "x-capture-token: $TOSHO_CAPTURE_TOKEN" \
     --data-binary @- <<'JSON'
   {"text": "ТЕКСТ ЗАДАЧІ"}
   JSON
   ```

   Текст може бути будь-якої довжини — зайве обріжеться на боці CRM. Лапки й
   переноси рядків усередині JSON екрануй.

3. **Покажи відповідь.** У JSON є готове поле `message` — виведи його як є,
   нічого не переказуючи своїми словами. Там уже є номер картки, назва,
   класифікація й посилання на дошку.

## Якщо не вийшло

- `401` — токен не збігся. Перевір, чи виставлена змінна `TOSHO_CAPTURE_TOKEN`
  (`echo ${TOSHO_CAPTURE_TOKEN:+є}`). Сам токен не показуй і не вгадуй.
- `503` — захоплення ще не налаштоване на боці CRM. Скажи про це і зупинись.
- `400` — текст порожній або закороткий. Перепитай, що саме записати.
- Мережа не відповіла — скажи чесно, що не записав, і покажи текст, який
  збирався надіслати, щоб він не пропав.

Не пробуй інші адреси й не вигадуй запасних шляхів: якщо ендпоінт мовчить,
задачу треба завести руками на https://tosho.pro/dev-requests.
````

## Обслуговування

**Ротація токена.** Згенеруй новий `openssl rand -hex 32`, онови
`DEV_REQUEST_CAPTURE_TOKEN` у Netlify, задеплой, онови `TOSHO_CAPTURE_TOKEN` у
`~/.zshrc`. Старий перестає працювати з моменту деплою.

**Вимкнути.** Прибери `DEV_REQUEST_CAPTURE_TOKEN` із Netlify й задеплой —
ендпоінт повернеться до `503` і перестане робити будь-що.

**Скільки коштує.** Кожне захоплення — один виклик моделі. Вартість лягає в
`tosho.ai_usage` з `metadata.source = "dev_request_cowork"`, видно у вкладці
«AI-кости» розділу спостережуваності — там же, де диктування й бот.

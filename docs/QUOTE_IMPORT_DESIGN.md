# QUOTE_IMPORT_DESIGN.md — імпорт позицій прорахунку з Excel-файлу

> Статус: **ПОГОДЖЕНО** (Артем, 2026-09-01). Картка: REQ-233 (чекліст p1–p4).
> Референсний вхід: запит «KMZ Industries» — 1 аркуш, ~25 позицій (30 рядків з
> альтернативами), колонки «№ · Найменування · Тираж · Вартість виробу (з ПДВ) ·
> Вартість нанесення · Коментар · Посилання», 30 гіперпосилань на сайти
> постачальників. Дані брудні: ціни текстом («319,00 (без ПДВ)», «прохання
> запитати підрядника»), діапазони «300-500 шт.», альтернативні товари в
> сусідніх рядках, позиції без ціни.

---

## 1. Мета

Менеджер отримує запит ексель-файлом і зараз вбиває його в CRM руками:
~150 полів плюс ходіння по сайтах за назвами й картинками — година-дві рутини
з помилками. Треба: кинув файл на картку прорахунку → перевірив прев'ю →
позиції з тиражами й цінами створені, а картинки та назви товарів
постачальника доїжджають фоном.

Принципи (звідси випливає вся архітектура):

- **Функція розшифровує — фронт записує.** AI-функція нічого не пише в базу;
  запис роблять наявні мутації з фронта під RLS користувача.
- **AI лише там, де без нього ніяк** — розбір брудної таблиці. Дослідження
  лінків (og-теги) робить звичайний код, безкоштовно.
- **Людина підтверджує все, що пишеться.** Прев'ю — обов'язковий крок, бо
  тиражі в CRM автозберігаються, а вхідні дані брудні.

## 2. Потік менеджера

1. Картка прорахунку → поруч із «Додати позицію» дія «Імпорт з файлу»
   (точне місце контрола узгоджується на живому UI; нового тулбара немає).
2. Менеджер кидає файл xlsx/xls/xlsm/csv. Браузер читає його **сам** (SheetJS)
   і шле на сервер текстовий дамп рядків + гіперпосилання — не файл.
3. 5–15 с «Розшифровую…» → **прев'ю-таблиця**: рядки з чекбоксами (всі
   увімкнені), колонки «назва · тиражі · ціна виробу · з ПДВ/без · нанесення ·
   коментар · лінк». Беджі на брудних місцях: «без ціни», «спитати
   підрядника», «300–500 → два тиражі», «альтернатива». Прості поля
   редагуються прямо в прев'ю.
4. «Створити N позицій» → позиції з'являються в прорахунку, тост.
5. Одразу стартує фонове дослідження: картинка й назва товару постачальника
   доїжджають на картки позицій поступово. Фронт рефетчить позиції ~кожні 5 с
   до завершення (стеля 2 хв), реалтайму немає.

## 3. Компоненти

### 3.1. Читання файлу на фронті

- SheetJS (`xlsx`) читає всі чотири формати, включно зі старим `.xls` і
  `.xlsm`, та віддає гіперпосилання комірок.
- Дамп: рядки TSV-подібним текстом (порожні рядки викидаються) + окремий
  список `{row, url}` для гіперпосилань. Багатоаркушевий файл — усі
  непорожні аркуші з заголовками `=== Аркуш: <назва>`.
- Стеля дампа ~250 кБ; більше — відмова з поясненням ще до сервера.

### 3.2. Функція `quote-import-parse` (нова, netlify/functions)

- Вхід: `{quoteId, fileName, sheetDump}`. Перевірка JWT + членства в команді
  прорахунку — патерном наявних функцій (`tosho-ai.ts`).
- Виклик OpenAI **Responses API** (той самий `fetch` на
  `api.openai.com/v1/responses`, що в `tosho-ai.ts`) зі **structured output**
  (json_schema, strict). Схема відповіді:

  ```
  items[]: {
    sourceRows: number[],           // рядки файлу, з яких зібрана позиція
    name: string,
    comment?: string,               // коментар замовника → item.description
    links: string[],
    runs[]: {
      quantity: number,
      unitPriceModel?: number,      // ціна виробу за шт.
      modelPriceIncludesVat?: bool, // «з ПДВ» / «без ПДВ» з тексту
      unitPricePrint?: number       // нанесення за шт.
    },
    flags: ("price_missing"|"ask_supplier"|"quantity_range"|"alternative")[],
    notes?: string
  }
  warnings: string[]                // що модель не змогла розібрати
  ```

- Модель: env `QUOTE_IMPORT_OPENAI_MODEL`, дефолт `gpt-5.6-terra` (баланс
  якості для брудних таблиць; luna лишається опцією через env).
- Витрати: `chatCostUsd` з `_aiPricing.ts` + запис у `_aiUsageLog` — як усі
  AI-виклики.
- Функція **нічого не пише в базу** — чиста розшифровка, повертає JSON.

### 3.3. Прев'ю і запис (фронт)

- Запис іде тим самим шляхом, що ручне додавання позиції:
  `insertQuoteItemRow` + тиражі через `persistQuoteRuns`/`upsertQuoteRuns`
  (`src/features/quotes/quote-details/queries.ts`). Жодного привілейованого
  запису, все під RLS користувача.
- Мапінг полів:

  | З розшифровки | Куди в CRM |
  |---|---|
  | `name` | `quote_items.name` |
  | `comment` | `quote_items.description` |
  | `links[0]` | `item.metadata.supplierUrl` (наявна кнопка «Постачальник») |
  | `links[]` повністю | `item.metadata.importLinks` |
  | `runs[].quantity` | `quote_item_runs.quantity` |
  | `runs[].unitPriceModel` | `quote_item_runs.unit_price_model` |
  | `runs[].modelPriceIncludesVat` | `quote_item_runs.unit_price_model_vat` (REQ-232) |
  | `runs[].unitPricePrint` | `quote_item_runs.unit_price_print` |

- Слід імпорту: `item.metadata.import = {fileName, importedAt, sourceRows}` —
  щоб на картці можна було відрізнити імпортовану позицію й дебажити розбір.

### 3.4. Функція `quote-import-research` (нова, background)

- Netlify background function (прецедент — `*-background.ts`): відповідає 202,
  працює до 15 хв. Вхід: `{quoteId, itemIds}`; JWT + перевірка, що позиції
  належать прорахунку й користувач має до нього доступ.
- Для кожної позиції з `supplierUrl`: SSRF-безпечний fetch HTML → витяг
  `og:image` / `og:title` (fallback: `twitter:image`, `<title>`) **звичайним
  кодом, без AI** → завантаження картинки → `sharp` → webp → Storage
  (`teams/{teamId}/quote-imports/{quoteId}/{itemId}.webp`, у бакеті й зі
  способом видачі URL, якими сьогодні живуть картинки
  `metadata.catalogVariant.imageUrl`) → запис у metadata позиції.
- Запис (привілейований, лише `metadata` позицій цього прорахунку, цін не
  торкається):
  - `metadata.catalogVariant = {name: <og:title, обрізаний>, imageUrl}` —
    UI картки позиції рендерить це поле вже сьогодні, без змін у UI;
  - `metadata.research = {status: "done"|"failed"|"skipped", fetchedAt,
    error?}` — для беджа «не вдалося підтягнути».
- SSRF guard і обмеження — виносяться в спільний `_lib`-хелпер із
  `catalog-image-import.ts` (перевірка публічних IP, http/https, browser-like
  заголовки, дозволені image content-type). Ліміти: 40 лінків за запуск,
  таймаут ~10 с на сайт, HTML ≤ 5 МБ, картинка ≤ 15 МБ. Помилка на одному
  сайті не валить решту.

## 4. Правила розшифровки (промпт)

- Ціни — тільки числа з файлу; текст замість ціни → прапорець
  (`price_missing` / `ask_supplier`), **не вигадана ціна**.
- «300-500 шт.» → два тиражі (300 і 500) однієї позиції — тиражі в CRM і є
  взаємовиключними варіантами (`quantity_range`).
- «без ПДВ» у тексті ціни → `modelPriceIncludesVat: false`; явне «з ПДВ» →
  `true`; колонковий заголовок «(з ПДВ)» — дефолт для колонки.
- Альтернативний товар у сусідньому рядку (той самий №, інший лінк/ціна) →
  окрема позиція з прапорцем `alternative`; менеджер зайве прибере у прев'ю.
- Рядки без назви й цін (шапки, підсумки) — пропускати, згадувати у
  `warnings`.

## 5. Безпека

- `quote-import-parse`: не пише нічого; стеля розміру дампа; JWT + доступ до
  прорахунку; секрети OpenAI лише в env.
- `quote-import-research`: SSRF guard (публічні IP, http/https), ліміти
  розмірів і кількості, привілейований запис обмежений `metadata` позицій
  одного прорахунку після user-scoped перевірки (патерн AGENTS.md «auth
  first, privileged write second»).
- Прев'ю = людське підтвердження всього, що пишеться; дослідження пише лише
  косметику, не ціни.
- Перед «готово» — `/security-review` обох функцій (REQ-233#p4).

## 6. Свідомо НЕ в v1

- Вгадування/створення клієнта і прорахунку з файлу (імпорт працює тільки в
  відкритий прорахунок).
- PDF, фото таблиць, vision-моделі.
- Матчинг позицій до каталогу CRM (`catalog_models`) — окрема картка, якщо
  захочеться.
- Реалтайм-прогрес дослідження (досить поллінгу) і AI-описи товарів.

## 7. Вартість

- Розшифровка: ~8–12 тис. токенів вхід + 3–5 тис. вихід на файл із ~30
  позицій ≈ **$0.06–0.10** на `gpt-5.6-terra` (на luna — ~пів цента).
- Дослідження: $0 — AI не бере участі.
- Усе лягає в наявний облік `ai_usage` (видно в адмінці).

## 8. Перевірка

- Юніт-тести чистої логіки: нормалізація дампа з SheetJS; мапінг відповіді
  моделі → payload мутацій (граничні кейси: діапазон тиражу, «без ПДВ», без
  ціни, кілька лінків, альтернатива); og-екстрактор на збережених
  HTML-фікстурах.
- Живий прогін у браузері (поведінка UI — прев'ю обов'язкове за правилами
  репо).
- Acceptance: реальна екселька KMZ → 25 позицій із тиражами, цінами і
  прапорцями ПДВ; картинки/назви доїхали фоном; витрата в `ai_usage`
  відповідає очікуванню.

# Контур, у якому зміна ламається до прода

Дата: 2026-09-06
Статус: погоджено (Артем), готово до реалізації
Картки: REQ-217, REQ-108, REQ-103

## Контекст

Три картки заводились окремо — про рахунок за хмару, про підагентів і про
вартість прев'ю. Розбір 06.09.2026 показав, що вони описують одну діру, і
знайшов свіжий доказ її існування.

### Доказ: чистка журналу мовчить пів року

`activity-log-retention` у проді запланована й активна (`cron.job`, `40 0 * * *`),
джоб щодня звітує «succeeded», на дошці здоров'я зелено. Архівується при цьому
нуль рядків.

Причина — у [netlify/functions/activity-log-retention.ts:44](../../../netlify/functions/activity-log-retention.ts):

```js
adminClient.rpc("archive_activity_log_all", { batch_limit: 5000, max_rounds: 50 })
```

Дві незалежні помилки в одному виклику:

1. **Немає `.schema("tosho")`.** RPC живе в `tosho`, клієнт за замовчуванням
   ходить у `public`. Решта дев'яти викликів RPC у `netlify/functions` схему
   вказують — цей єдиний ні.
2. **Чужі імена аргументів.** База чекає `p_batch_limit` / `p_max_rounds`
   (`tosho.archive_activity_log_all(p_batch_limit integer, p_max_rounds integer)`).

PostgREST на будь-яку з двох відповідає 404, функція повертає 500.

Стан даних на 06.09.2026:

| | |
|---|---|
| `tosho.activity_log_archive` | 181 рядок, найсвіжіший **06.03.2026** |
| `public.activity_log` | 10 095 рядків, найстаріший **02.01.2026** |
| Останній прогін крона | 06.09.2026 00:40, «succeeded», перенесено 0 |

### Чому цього ніхто не побачив

`typecheck` пройшов — `.rpc()` типізований як `any` для невідомих імен.
`lint` пройшов — синтаксис коректний. `check-netlify-functions` пройшов — ім'я
файлу валідне. `check-cron-endpoints` пройшов — адреса, на яку стукає крон,
справді існує. Деплой пройшов. Крон стукає, Netlify відповідає, `net.http_post`
рапортує «succeeded», бо він і не знає про відповідь.

Тобто **жодна з сімнадцяти перевірок не дивиться всередину виклику**, а
`net.http_post` за побудовою мовчазний. Це рівно той клас поломки, заради якого
свого часу завели `check-cron-endpoints.mjs` («поломка МОВЧАЗНА з обох боків»),
тільки на шар глибше: адреса жива, а виклик усередині — ні.

### Що з цього випливає для REQ-103

Картка питала, де ми дивимось на зміну перед викочуванням. Відповідь, яку дає
цей інцидент: **прев'ю не врятувало б.** Щоб баг виліз, треба було власноруч
смикнути крон-функцію й прочитати відповідь. Ніхто б цього не зробив — саме тому
вона й мовчала пів року.

Прев'ю — місце, куди людина *може* заглянути. Цей клас поломок ловиться лише
тим, що спрацьовує *без* людини.

Розбір чотирьох вжитків прев'ю з тіла REQ-103:

| Вжиток | Чи потрібен Netlify |
|---|---|
| Заміри на справжній збірці | Ні — `npm run build && npm run preview` |
| Playwright проти збірки | Ні — `npm run e2e` проти `vite preview` |
| Функції на справжньому рантаймі | Ні — прев'ю тут не допомагає (див. вище) |
| Показати комусь за посиланням | **Так**, і замінити нічим |

### Що з цього випливає для REQ-108

Картка описувала `function-reviewer` як агента. Але сьогоднішній баг —
детермінований: ім'я схеми й імена аргументів звіряються з `pg_proc` запитом,
без жодної моделі. Агент за тими самими критеріями коштує токени щоразу й
іноді помиляється; ратчет коштує нуль і не забувається.

Тому REQ-108 розщеплюється: детерміноване — у ратчет, суб'єктивне — в агента.

## A. Полагодити чистку журналу (REQ-217)

`netlify/functions/activity-log-retention.ts`, рядок 44:

```js
const { data, error } = await adminClient
  .schema("tosho")
  .rpc("archive_activity_log_all", { p_batch_limit: 5000, p_max_rounds: 50 });
```

**Доказом вважається рух даних, а не зелений `check`.** Після деплою звірити
запитом у базу:

- `max(created_at)` у `tosho.activity_log_archive` зрушив із 06.03.2026;
- `count(*)` у `public.activity_log` просів із 10 095;
- відповідь функції містить `archived > 0`.

Поки цифри не зрушили — пункт не закритий, хоч би що казав крон.

Заразом по картці:

- **p1** («крон на 5 хвилин») закрити — фактично в проді з 05.09:
  `reminders-minute` стоїть на `*/5 * * * *`, 863 успішні прогони за 72 год
  (= 288 на добу замість 1440).
- **p2** («звірити білінг») — цифри Netlify з сесії не читаються,
  `NETLIFY_API_TOKEN` живе в оточенні Netlify. Беремо з інтенту
  `hosting_usage` в боті (`netlify/functions/_adminAssistant.ts`), а не з ока.

## B. Ратчет `check:rpc-contracts` (нове ядро REQ-108)

`scripts/check-rpc-contracts.mjs` — за зразком `check-cron-endpoints.mjs`.

**Що робить.** Збирає з дерева всі виклики `.rpc("ім'я", { … })` у
`netlify/functions` і `src`, визначає для кожного схему (явний `.schema("…")`
у ланцюжку або `public` за замовчуванням) і набір імен аргументів. Звіряє з
живою базою:

```sql
select n.nspname, p.proname, pg_get_function_identity_arguments(p.oid)
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname in ('public','tosho');
```

Падає, коли: функції з таким іменем немає у вказаній схемі; або імена
аргументів у виклику не збігаються з іменами параметрів.

**Угоди, успадковані від сусідніх перевірок:**

- **Немає доступу до бази** (CI, свіжий клон, чужа машина) — мовчки пропускаємо.
  Перевірка з даних, яких немає, гірша за її відсутність.
- **Базовий рівень НЕ потрібен** — на відміну від `check-db-guards`. Зонд
  06.09.2026 пройшов усі 20 викликів `.rpc()` у дереві й знайшов рівно одне
  розходження — той самий баг із розділу A. Гасити нема чого, тож ратчет
  падає просто на всьому, що не збігається.
- Місце в `scripts/run-checks.sh` — поруч із рядком «адреси кронів», у тій же
  групі, що вимагає бази.

**Межа.** Ратчет звіряє контракт виклику, а не його зміст. Чи має право ця
функція викликати цей RPC — питання до `function-reviewer` (розділ C).

## C. Два агенти на те, що ратчетом не візьмеш (решта REQ-108)

Обидва — `.claude/agents/*.md`, `model: sonnet`, вузький набір інструментів.

**`rls-verifier`** — лише `Bash`. Приймає таблицю або політику, приміряє `anon`,
`authenticated` і конкретного користувача через
`set_config('request.jwt.claims', …)`, читає рядки назад і повертає таблицю
«хто що бачить і що може записати». `psql` за шляхом
`/opt/homebrew/opt/libpq/bin/psql`, рядок підключення — **за іменем змінної
`BACKUP_DB_URL`**, ніколи значенням: `.claude/agents/*.md` комітяться, репозиторій
публічний.

**`function-reviewer`** — звіряє дифф Netlify-функції з чеклістом
`docs/SECURITY.md`: JWT, авторизація дії, service-role лише на запис, коди
401/403 замість 500, схема тіла. **Явно НЕ перевіряє те, що вже робить ратчет
B** — інакше платимо токенами за роботу, яка коштує нуль.

Правило CLAUDE.md «рецензент лише там, де помилка дорога» лишається чинним:
картка не додає рецензій, вона замінює дорогі дешевими там, де перевірка
механічна.

**Не робимо:** `ui-checker` — викинуто ще в тілі REQ-108 (REQ-140 робить це
краще: Playwright на зібраному застосунку, вісім сценаріїв).

## D. Замір прев'ю й чесний запис у політиці (REQ-103)

**Дія Артема, не агента:** увімкнути branch deploys для `preview/*` у
Netlify → Site → Build & deploy → Branches. У налаштування акаунта агент не лізе.

**Ціна заміру.** Зміна `netlify.toml` сама собою спричиняє продакшн-збірку
(файл не входить у список виключень `ignore`). Але локально вже накопичено 21
непушений коміт, тобто один продакшн-деплой і так неминучий: якщо покласти
зміну в ту саму пачку, вона коштує **нуль зверху**. Платним лишається рівно
те, що міряємо — сам branch-деплой, 0 або 15 кредитів.

**Хід заміру:** обмежити перший рядок `ignore` до `deploy-preview`, запушити
гілку `preview/netlify-cost` із будь-якою правкою в `src/`, після збірки
подивитись Team → Billing → Credit usage breakdown.

**Що переписуємо за результатом.**

`docs/DEPLOY_POLICY.md` §5.3 зараз каже «перевірено 29.08.2026», тоді як §2 у
тому ж файлі зізнається «за документацією Netlify». Документ, який керує
витратами, не має видавати припущення за факт — §5.3 переписати під **замір**,
хай яким він вийде.

§3.3 («Артем дивиться зміни локально — це `npm run dev`») переписати під те, що
насправді заміняє «подивитись»:

- заміри продуктивності — `npm run build && npm run preview`, бо dev завищує
  приблизно вдесятеро;
- мовчазні поломки — ратчети з розділу B, а не людське око;
- прев'ю — рівно для «показати людині за посиланням», єдиного вжитку, який
  нічим не замінюється.

Якщо замір покаже 15 кредитів — записуємо це й приймаємо, що показ людині
коштує 15 кредитів за раз. Це ціна, а не заборона (§4).

## Порядок і ціна

**B → A → C → D.** Ратчет пишеться ПЕРШИМ, до правки: тоді він падає на
живому дереві зі справжнім багом, і ми бачимо, що він працює, а не віримо
на слово. Правка з розділу A після цього перевіряється тим, що ратчет
зеленіє. Заразом справжній виклик лягає фікстурою в юніт-тест розбирача —
регресія зафіксована назавжди, незалежно від порядку.

(Спека спершу мала порядок A → B; замінено 06.09.2026 під час написання
плану, бо тест на справжньому багу сильніший за обіцянку.)

| Блок | Кредити на розробку |
|---|---|
| A | 0 (правка їде в загальній пачці) |
| B | 0 (`scripts/*.mjs` не входить у виключення, але їде тією ж пачкою) |
| C | 0 (`.claude/*.md` — білд не запускається взагалі) |
| D | 0 або 15, залежно від заміру |

Викочування A+B+C — один спільний деплой на всі накопичені коміти.

## 1. Навіщо

Три виміряні дефекти, а не відчуття.

**Стани зроблені через `opacity`, а прозорість не знає про тему.** `hover:opacity-85` на світлому фоні (`--background` 98.8%) кнопку освітлює, на темному (7.8%) — гасить у бруд. Одне правило, протилежний ефект. `disabled:opacity-50` у темній темі бере `--destructive` 357 95% 64% і перетворює на багно, а `--destructive-foreground` при 50% падає нижче порогу читабельності.

**Іконка не масштабується.** У базі `button.tsx` зашито `[&_svg]:size-4` і `gap-2` — однаково для всіх десяти розмірів. У робочій кнопці `sm` (360 використань) це 16-піксельна іконка поруч із 12-піксельним текстом: іконка більша за підпис у 1.33 раза й займає половину висоти.

**Відступи їдуть непослідовно.** Відношення відступу до висоти: `xxs` 0.33 → `xs` 0.36 → `sm` 0.375 → `md` 0.44 → `lg` 0.50. Малі затиснуті, великі розхлябані.

## 2. Зразок, до якого рівняємось

[`BoardFilters.tsx`](../../../src/features/devRequests/BoardFilters.tsx) і [`GroupControl.tsx`](../../../src/features/devRequests/GroupControl.tsx) на дошці запитів. Артем назвав їх найкращим контролом у CRM; розбір показав, що подобається не вигляд, а сім структурних властивостей:

1. **Ряд не росте від даних.** Чіпи розсипом замінені однією кнопкою з числом — ширина тулбара більше не залежить від кількості тем.
2. **Усе на одній висоті.** Контрол сидить на `TOOLBAR_CONTROL` (40px), як і поле пошуку. Чіп 28px не сідав на одну лінію — тулбар виглядав зібраним нашвидкуруч.
3. **Стан видно, не відкриваючи.** Тригер підсвічується й показує лічильник активних фільтрів.
4. **Вибране лишається зовні.** Зняти фільтр можна не відкриваючи панель; чіп там доречний, бо він уже позначка стану, а не орган керування.
5. **Нічого не стрибає.** `slide={false}`; галочка займає місце завжди (`opacity-0`, не `hidden`).
6. **Числа біля кожного рядка**, `tabular-nums`.
7. **Порожні варіанти показані, але тьмяні й без кліку** — у списку це правда, у ряду було б брехнею.

**Ці сім правил — критерій приймання для всієї роботи, не тільки для Хвилі 1.**

### Чого НЕ чіпаємо і чому

**Висоти.** `h-6/7/8/9/10` спарені з `Input` і стоять поруч у панелях. Зміна зламала б вирівнювання скрізь.

**Драбину радіусів** (`rounded-md` → `rounded-lg` → `rounded-xl` за висотою) лишаємо як є: вона збігається з `Input` пік у пік і тримає концентричність у табах. Зміщується лише **база** `--radius` — див. 6-біс. Пропорція радіуса до висоти справді гуляє (0.25 на `sm`, 0.35 на `lg`), але вирівнювати саме її означало б розсинхронити кнопку з полем поруч. Гірший розмін.

**Набір варіантів.** 15 варіантів лишаються як є. Міняються тільки їхні стани.

## 4. Нові токени

Додати в `src/index.css` у `:root` і `.dark`.

```css
/* :root — світла */
--control-disabled-bg:     0 0% 93.5%;
--control-disabled-fg:     0 0% 63%;
--control-disabled-border: 0 0% 89%;

/* .dark */
--control-disabled-bg:     0 0% 13.5%;
--control-disabled-fg:     0 0% 39%;
--control-disabled-border: 0 0% 16%;
```

Назва `--control-*`, а не `--btn-*`, навмисно: ті самі три токени обслуговують і кнопку, і `CONTROL_BASE`. Поле й кнопка, що стоять поруч у панелі, у заблокованому стані мають виглядати однаково.

### Похідні стани — окремий випадок

```css
/* Тримає повний колір, НЕ трійку HSL — свідомий виняток із конвенції файлу.
   Похідне від --foreground, тож зміна теми чи бренду підхоплюється сама.
   Вживати як var(--btn-solid-hover), без обгортки hsl(). */
--btn-solid-hover:  color-mix(in oklab, hsl(var(--foreground)) 88%, hsl(var(--background)));
--btn-solid-active: color-mix(in oklab, hsl(var(--foreground)) 79%, hsl(var(--background)));
--btn-danger-hover:  color-mix(in oklab, hsl(var(--destructive)) 87%, hsl(var(--background)));
--btn-danger-active: color-mix(in oklab, hsl(var(--destructive)) 78%, hsl(var(--background)));
```

Чому `color-mix` у бік `--background`, а не окремі значення на тему: «у бік фону» автоматично означає протилежні напрямки у світлій і темній. Один запис — правильний результат в обох. Це і є та поломка, яку лагодимо; жорсткі значення просто перенесли б її в інше місце.

Ці чотири токени оголошуються **один раз у `:root`** — не дублюються в `.dark`, бо самі посилаються на токени, що там перевизначені.

### Моушен-токени (додано аудитом 2026-08-15)

У базі шість сирих тривалостей (`duration-100/150/200/220/300/500`) і дві кастомні криві на всю систему. Хвиля 1 не додає сьому тривалість і третю inline-криву, а заводить токени й сама ж їх споживає:

```js
// tailwind.config.js → theme.extend
transitionDuration: {
  fast: "110ms",   // натиск — коротший за відпускання
  base: "160ms",   // стандартний перехід станів
  slow: "240ms",   // розгортання, поява панелей
},
transitionTimingFunction: {
  out: "cubic-bezier(.32,.72,0,1)",   // пружне виринання
},
```

Кнопка вживає `duration-base ease-out` для кольорів/тіні й `duration-fast` для transform. Змітання сирих значень по решті бази — Хвиля 3, тут лише джерело.

## 5. `button.tsx`

### 5.1 База

**Прибрати:**
- `[&_svg]:size-4` і `gap-2` → переїжджають у розміри
- `text-[16px] leading-[24.8px]` → мертвий код: кожен size задає власний `text-*`, який перебиває і кегль, і інтерліньяж

**Замінити:**
- `tracking-[0.2px]` → `tracking-[0.01em]`. Абсолютний трекінг на тексті від 10px до 16px оптично вдвічі сильніший на дрібному.
- `transition-all duration-150 ease-out` → перелік властивостей + токени (див. §4, «Моушен-токени»):
  ```
  transition-[background-color,border-color,color,box-shadow,transform,opacity]
  duration-base ease-out  (transform — duration-fast)
  ```
  `transition-all` анімує зокрема властивості, що впливають на розкладку; сирі `cubic-bezier` у className не пишемо — крива живе в конфігу.

**Перевірити окремо:** `[&_svg]:-mt-[0.5px]` — оптичний зсув, підібраний під іконку 16px. Після того, як іконки стануть 12–16px, його треба переглянути очима: або лишити, або зробити частиною розміру, або прибрати. Не вирішувати наосліп.

| `lg` | `h-10` 40 | `px-4` **16** ← було 20 | `text-base` **16** ← було `text-[15px]` | `size-4` 16 | `gap-2` 8 | `rounded-xl` 14 |

Відступ тримає відношення ≈0.375 від висоти по всій шкалі. Опорна точка — `sm`, бо це 360 із ~700 кнопок: підтягуємо шкалу до вже звичного, а не навпаки.

**`xs` і `sm` свідомо лишаються обидва на 12px.** Дубль у шкалі кеглів — не дефект: їх розрізняють висота й відступ, а 11px на клікабельному підписі вже дрібно.

**`compact`** (`h-7 rounded-md px-3 text-xs`) не вживається жодного разу і дублює `xs` за висотою з іншим відступом. Позначити `@deprecated` у коментарі, **не видаляти** — рішення про видалення за Артемом.

### 5.3 Стани

Однаково для всіх варіантів, крім прописаних окремо.

| Стан | Правило |
|---|---|
| **hover** (заливні: `primary`, `destructiveSolid`) | `bg: var(--btn-solid-hover)` / `var(--btn-danger-hover)`. **Прибрати `hover:opacity-85`.** |
| **hover** (поверхневі: `secondary`, `outline`, `ghost`) | підняти наявний фон на щабель (`bg-muted/40` → `bg-muted`), як зараз |
| **active** | фон на `*-active`, `scale-[0.972]`, **`shadow-none`** — кнопка сідає, а не просто зменшується |
| **disabled** | `bg-control-disabled`, `text-control-disabled-fg`, `border-control-disabled-border`, `shadow-none`, знятий ring. **Прибрати `disabled:opacity-50`.** |
| **focus-visible** | лишається як є (`ring-2 ring-ring/50 ring-offset-1`) |
| **loading** | див. 5.4 |

**`destructive` (рамковий)** окремо: рамку `border-destructive/30` замінити на `border-danger-soft-border` — токен існує саме для цього й підібраний під кожну тему. На наведенні `bg-danger-soft` + рамка підсилюється до `border-destructive/55`. На натиску фон домішує червоний.

### 5.4 Стан завантаження

Новий проп `loading?: boolean` у `ButtonProps`.

Поведінка:
- спінер стає **на місце провідної іконки**, підпис лишається видимим — ширина не змінюється жодного пікселя, бо іконка й спінер однакового розміру;
- `aria-busy="true"`, `aria-disabled="true"`, `pointer-events: none`;
- **не ставити атрибут `disabled`** — заблокована й зайнята кнопки мають різний вигляд і різний зміст для читача з екрана;
- колір кнопки зберігається, підпис злегка гасне (`opacity: .85`).

Спінер — кільце з доріжкою й головкою (коло `stroke-opacity: .28` + дуга), не гола дуга. Обертання через CSS із **обов'язковими** `transform-box: fill-box; transform-origin: 50% 50%` — інакше SVG крутиться навколо кута.

Це закриває `Loader2`, вручну розставлений у **58 файлах**. Міграцію цих місць у Хвилю 1 **не включаємо** — новий проп зʼявляється, старі місця переводяться поступово.

### 5.5 Моушен

**CSS для постійних станів** (наведення, натиск, фокус) — працює на всіх ~700 кнопках і коштує нуль виконання.

**framer-motion лише на морфінг завантаження й підтвердження успіху** — такі кнопки на екрані одиничні.

**Заборонено:** обгортати `Button` у `motion.button`. На дошці й у таблицях рендеряться сотні кнопок; інстанс framer-motion на кожну — помітна втрата швидкості на вже важких сторінках.

Крива натиску — токен `ease-out` (`cubic-bezier(.32,.72,0,1)`), тривалість натиску коротша за відпускання: `duration-fast` (110ms) проти `duration-base` (160ms).

Усе під `@media (prefers-reduced-motion: reduce)` вимикається.

## 6. `controlStyles.ts`

### 6.1 Стан помилки — новий

`CONTROL_BASE` зараз має `hover`, `focus-visible`, `disabled` і **жодного** стану помилки, при тому що форми в CRM усюди.

```
aria-[invalid=true]:border-destructive/60
aria-[invalid=true]:bg-danger-soft/30
aria-[invalid=true]:focus-visible:border-destructive
```

Через `aria-invalid`, а не клас: атрибут одночасно повідомляє читача з екрана, тобто доступність і вигляд не розʼїжджаються.

### 6.2 Заблокований стан — на спільні токени

Замінити `disabled:opacity-60 disabled:bg-muted/20` на ті самі `--control-*` токени, що й у кнопки. Поле й кнопка поруч у панелі мають виглядати однаково заблокованими.

### 6.3 Колір іконки більше не прибивається до сірого

Рядок 20 `controlStyles.ts`:

```
[&>svg]:text-muted-foreground   ← прицвяховує прямий svg до сірого
hover:[&>svg]:text-foreground
```

Правило перебиває успадкування `currentColor`. Тому коли тулбарна кнопка вмикається й отримує `text-primary`, **іконка лишається сірою** — вона не слухає колір кнопки, бо їй колір заданий напряму. У прямому вигляді: синій текст, сіра іконка, сіра стрілочка.

Показово, що **в `input.tsx` немає жодного svg** — у полях, під які це правило вочевидь писали, воно ніколи не спрацьовує. Спрацьовує на тулбарних кнопках і селектах: **14 файлів, ~40 іконок**.

**Рішення — розчепити відповідальності:**
- `CONTROL_BASE` лишає геометрію, поверхню й стани. **Правила кольору іконки прибрати.**
- Глушіння стрілочки переїжджає в `select.tsx` — там воно доречне: у селекті стрілка це підказка, а не зміст.
- Тулбарні кнопки після цього успадковують `currentColor`: активний стан фарбує іконку сам, без окремого правила.

Окремо: `ChevronDown` у `GroupControl.tsx` має власний `opacity-60`. Замінити на успадкування `currentColor` з опційним `opacity-70`, щоб стрілка тонувалась разом зі станом.

### 6.4 Чого тут не робимо

`SEGMENTED_TRIGGER` і `SEGMENTED_TRIGGER_SM` дублюють одні й ті самі правила — **Хвиля 2**. Тут лише база контролів.

## 6-біс. Радіус: 10 → 8px

`--radius: 0.625rem` → `0.5rem`. Одна ручка, узгоджено рухає **873 місця**:

| клас | значення після | вживань |
|---|---|---|
| `rounded-sm` | 4 | 24 |
| `rounded-md` | 6 | 143 |
| `rounded-lg` | 8 | 255 |
| `rounded-xl` | 12 | 295 |
| `rounded-2xl` | 16 | 103 |
| `rounded-4xl` | 22 | 52 |

Кнопка: `xxs/xs/sm` 6 · `md` 8 · `lg` 12.

**Таби переживають зміну самі.** Вкладеність побудована за правилом концентричних радіусів, і воно дотримане точно:

```
SEGMENTED_GROUP     p-1   (4px) + rounded-xl (--radius + 4)
  └ TRIGGER                       rounded-lg (--radius)        різниця 4 = padding ✓
SEGMENTED_GROUP_SM  p-0.5 (2px) + rounded-lg (--radius)
  └ TRIGGER_SM                    rounded-md (--radius − 2)    різниця 2 = padding ✓
```

Обидва радіуси похідні від `--radius`, тож різниця — константа. Після зміни: група 12, тригер 8, різниця так само 4. Правити таби **не треба**.

**Що НЕ поїде за ручкою:**
- `rounded-full` — **615 місць**, і це правильно: коло лишається колом.
- **`rounded-[Npx]` жорстких — 81 місце.** Ось це ризик: частина з них зараз випадково збігається з драбиною, а після зміни розсинхронізується. **Вичистити тим самим заходом**, інакше повториться історія з кеглями.

До 6px не йдемо: там `rounded-sm` стає 2px, тобто фактично кут. Це вже інша естетика, а не підкрутка.

## 6-терц. Активні стани в тулбарі

**Фільтр і групування не можуть виглядати однаково.** Зараз обидва вмикаються байт-у-байт однаковим рядком:

```
border-primary/40 bg-primary/10 text-primary hover:bg-primary/15
```

При тому що коментар у `GroupControl.tsx` наполягає на протилежному: «фільтр прибирає картки з очей, групування не ховає жодної». Коли активні обидва — не видно, який із них ховає картки.

Фільтр лишає синій (він руйнує вигляд — має кричати). Групування отримує тихішу підсвітку: нейтральний тон, помітний, але без сигналу тривоги.

**Чіпи в тулбарі стають нейтральними.** Зараз вони беруть `toneSubtleClass[ZONE_TONE[zone]]`, а тони зон навмисно рознесені по колу (`accent` 262°, `teal`, `info`, `festive` 340°). На картці це правильно — чіп працює якорем серед десятків. У тулбарі, поруч із двома підсвіченими контролами, ряд стає веселкою з чотирьох кольорів.

Тон там надлишковий: у чіпі вже написано словом, який це фільтр. Нейтральний чіп згортає ряд до одного-двох кольорів, і «що ввімкнено» читається швидше.

`ZONE_TONE` на картках **не чіпаємо** — там він працює за призначенням.

## 7. Перевірка

`npx tsc --noEmit` і `npm run lint` — необхідні, але **недостатні**: обидва дефекти в прототипі (обрізані іконки, кривий спінер) були суто візуальні й жодну автоматичну перевірку не завалили.

**Обовʼязково очима, у застосунку, в обох темах:**

| Екран | Що дивимось |
|---|---|
| Дошка запитів `/dev/backlog` | `sm` у щільному списку — головна поверхня змін |
| Прорахунки, таблиця | кнопки в рядках, іконкові кнопки |
| Будь-яка форма | поле + кнопка поруч: однакова висота, однаковий заблокований стан, стан помилки |
| Тулбар | кнопка поруч із пошуком — одна оптична лінія |
| Заблоковані кнопки | у темній темі раніше виходило багно — головна перевірка |
| Тулбар з увімкненими фільтрами | іконка й стрілка мають синіти разом із текстом; фільтр і групування мають відрізнятись |
| Таби `/dev/backlog` після зміни `--radius` | вкладеність має лишитись концентричною без правок |

Прогнати `prefers-reduced-motion` і перевірити, що натиск не анімується.

**Мірило приймання:** сім правил із розділу 2. Якщо якийсь контрол після правки бреше про свій стан, стрибає або не сідає на спільну лінію — правка не закінчена.

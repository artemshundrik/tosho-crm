## 1. Мета

Акаунт перестає бути анкетою і стає «моїм зрізом» CRM (employee self-service, патерн BambooHR/Personio):
хто я → що в мене відбувається → мої відсутності/виплати → як система зі мною говорить.

## 2. Цільова структура

Вкладки в тулбарі (SEGMENTED_GROUP, як у `TeamPage`): **Огляд · Відсутності · Виплати · Налаштування**.

- **Огляд:** айдентика (аватар, чипи ролі, контакти) + таймлайн співпраці (старт → випробувальний → сьогодні),
  блок «Сьогодні» (мої задачі/нагадування), баланс відсутностей, мої заявки, виплати (гейтовано), heatmap активності (пізніше).
- **Відсутності:** мої заявки + баланс + `AbsenceDialog` (все вже існує в Команді — тут лише self-зріз).
- **Виплати:** мій зріз «Виплат команді» з Фінансів. **Гейт:** картка видима лише за module_access `finance`
  (реєстр `src/lib/moduleAccess.ts`) — доки CEO не вирішить питання видимості зарплат (див. §5).
- **Налаштування:** картки з власними футерами-«Зберегти» (Vercel-патерн): Особисті дані, Безпека (пароль, сесії),
  Telegram, Сповіщення.

## 3. Фази

### Фаза 1 — квік-віни (DONE, 20a5efe)

- `updateProfile` без `window.location.reload()` — шапка/меню оновлюються подіями `profile:name-updated` / `profile:avatar-updated`.
- Глобальна кнопка «Зберегти зміни» → футер картки «Особисті дані» (зберігається лише те, що редагується).
- Зміна пароля — інлайн-діалог (`supabase.auth.updateUser({ password })`), `/reset-password` лишається для forgot-flow.
- З героя видалено хардкод «Kyiv, UA» і плитки Старт/Стаж/Статус (дубль блоку «Робота в компанії»).

### Фаза 2 — каркас і Огляд (M)

- Вкладки через `usePageHeaderActions` + `UnifiedPageToolbar` (ProfilePage зараз не в цій системі — конверсія).
- Айдентика + таймлайн: дані вже завантажуються в ProfilePage (directory entry, employment) — чистий UI.
- Баланс/заявки: реюз `AbsenceBalanceMeters`, `AbsenceDialog` і self-scoped запитів Team 2.0 (RLS уже дозволяє свої рядки).
- «Сьогодні»: нагадування + мої дизайн-задачі/прорахунки. **Перф-правило:** реюз наявних кешів/директорій,
  жодних нових широких читань на першому рендері.
- Блок «Робота в компанії» розчиняється в айдентиці з таймлайном (прогрес випробувального переїжджає туди).

### Фаза 3 — вкладка «Налаштування» (S)

- Перенесення карток: Особисті дані, Безпека, Telegram, лінк-картка «Центр сповіщень».
- Сесії: чесний мінімум — поточна сесія + «Вийти всюди» (`signOut({ scope: "global" })`).
  Повний список пристроїв Supabase клієнту не віддає — не обіцяти в UI.

### Фаза 4 — сповіщення в акаунті (M)

- **НЕ нова модель.** Реюз реєстру `src/lib/notificationCategories.ts` + `channel_prefs`
  (див. `docs/TELEGRAM_NOTIFICATIONS_DESIGN.md`, фаза 2 — вже в коді, матриця живе в діалозі `NotificationsPage`).
- Задача фази: перенести/віддзеркалити матрицю «категорія × канал (in-app/push/telegram)» у вкладку «Налаштування»
  + UI тихих годин (серверна механіка 9:00–21:00 вже існує — лише експонувати).
- Heatmap активності на Огляді — з `activity_log` (Пульс), тільки після перф-оцінки (таблиця велика, потрібен агрегат).

## 4. Дизайн-мова

Тільки наявні токени: сегментні вкладки з `CountBadge`, тони зі `statusTones.ts`, метри квот як у карток команди,
`tabular-nums` на цифрах, чорна primary-кнопка, картки `rounded-inner border-border/40 shadow-card`. Референс — мокапи в артефакті.

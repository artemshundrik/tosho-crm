# DEPLOY POLICY — коли пушимо і скільки це коштує

Політика викочування tosho-crm у прод. Обов'язкова до виконання для будь-якого агента
(Claude Code, Codex) і для ручної роботи.

**Головне правило одним рядком: коміт — безкоштовний, пуш — коштує грошей. Пушимо пачками, за прямою командою.**

---

## 1. Словник

| Термін | Що це | Де живе | Ціна |
|---|---|---|---|
| **Коміт** (commit) | Збережена точка в історії коду з підписом, що змінено | Тільки локальна машина | 0 |
| **Пуш** (push) | Відправка накопичених комітів на GitHub | GitHub | 0 |
| **Деплой** (deploy) | Netlify бачить пуш, збирає сайт і викладає на tosho.pro | Netlify | **15 кредитів ≈ $0.15** |

Ланцюжок: `коміт → коміт → коміт → ПУШ → деплой → 15 кредитів`

Ключове: **один пуш = один деплой, скільки б комітів у ньому не було.**
Двадцять фіксів однією пачкою коштують ті самі 15 кредитів, що й один — тобто батчинг
економить не «квоту», а гроші: 20 окремих пушів це 300 кредитів (~$3), один пуш — 15 (~$0.15).

## 2. Скільки це коштує насправді

**Замір 29.08.2026** — Netlify UI → Billing → Credit usage breakdown + API. Тариф
**Personal, $9/міс = 1000 кредитів**, auto recharge вимкнений.

| Стаття | Тариф Netlify | Наш фактичний обсяг |
|---|---|---|
| Успішний production-деплой | **15 кредитів ≈ $0.15** | 10 деплоїв = рівно 150 кредитів (поточний період) |
| **Провалений** деплой | **0** | 5 падінь у липні-серпні не коштували нічого |
| Deploy Preview, branch-деплой | **0** | за документацією Netlify |
| Відкат на попередній деплой | **0** | за документацією Netlify |
| Compute (55 функцій + БД) | 10 кредитів за GB-год | 31 GB-год ≈ **310 кредитів/міс** |
| Веб-запити | 2 кредити за 10 тис. | 407 тис. ≈ 81 кредит/міс |
| Bandwidth | 20 кредитів за GB | 1.1 GB ≈ 22 кредити/міс |
| Форми, збірка (хвилини) | 0 | 164 хв за місяць — не тарифікуються |

**Фон** (усе, крім деплоїв) — **≈400–550 кредитів/міс**. Найбільший шматок у ньому не трафік,
а compute функцій: третина тарифу йде на те, що просто крутиться.

**Реальний місяць 27.07–26.08.2026:** 121 успішний деплой (+5 провалених), спожито ≈1 900
кредитів, заплачено **$19** — $9 за тариф і $10 доповненням 2 серпня (1000 кредитів по $0.01).
Тобто ліміт «1000 кредитів» перейшли вдвічі й нічого не зламалось — просто доплатили.

> Стара версія цього розділу (замір 02.08.2026) стверджувала, що після 1000 кредитів
> «деплої блокуються до 27-го». Це неправда двічі: по-перше, баланс докуповується вручну
> за $5 / 500 кредитів; по-друге, наслідок вичерпання гірший за «блокування деплоїв» —
> див. §4.

Що НЕ спричиняє деплоїв: build hooks (їх немає), GitHub Actions (окрема безкоштовна
платформа), крони — вони живуть у Supabase pg_cron.

## 3. Правила (жорсткі)

### 3.1 Агент НЕ пушить сам

Пуш дозволений **тільки** у двох випадках:

1. **Пряма команда Артема** в поточній розмові: «пушимо», «викочуй», «деплой», «залий у прод».
2. **Гарячий фікс**: прод зламаний, люди не можуть працювати. Тоді пушимо одразу без запиту —
   15 кредитів дешевші за простій. Про факт доповісти в тій же відповіді.

Усе інше — накопичуємо.

### 3.2 Що агент робить замість пуша

- Комітить локально стільки разів, скільки треба (безкоштовно).
- Кожен коміт — окремий і осмислений, щоб потім можна було відкотити точково.
- Верифікує **до** коміту: `npm run typecheck` + `npm run lint`. Це локально й безкоштовно.
- У кінці відповіді доповідає: **«накопичено N комітів, готові до викочування»** + список.
- Далі мовчки чекає команди. Не переконує, не пушить «щоб не забути».

### 3.3 Артем дивиться зміни локально

Перевірка перед викочуванням — це `npm run dev` на localhost, не деплой у прод.
Локальний перегляд безкоштовний і необмежений. **Ніколи не деплоїмо в прод «щоб подивитись».**

### 3.4 Гілки

Працюємо прямо в `main` (див. пам'ять `feedback_ship_directly_to_main` — та частина лишається
чинною). Змінилася тільки частина про пуш: раніше пушили кожен фікс, тепер — пачками за командою.

## 4. Бюджет: це не стеля, це ціна

1000 кредитів мінус фон (~450) — це **≈35-40 деплоїв на місяць у межах $9**. Але це не
стіна, за якою «не можна». Це точка, після якої **кожен деплой коштує ≈$0.15**
(Personal: 500 кредитів за $5, докуповуються вручну за одну хвилину).

| Тариф | Ціна | Кредитів/міс | Доповнення | Ціна деплою понад пакет |
|---|---|---|---|---|
| Free | $0 | 300 | — | — |
| **Personal (наш)** | **$9** | **1000** | 500 за $5 | **$0.15** |
| Pro | $20 | 3000 (щаблі до 20 000) | 1500 за $10 | $0.10 |

Квітневе оновлення 2026 зняло стару тезу «дорожчий тариф не рятує»: Pro тепер $20 за
3000 кредитів і безлімітні місця (було $19 **за місце**). За фактичним темпом
(~1900 кредитів/міс) Pro за $20 вигідніший, ніж Personal із доповненням ($19 за 2000).
Рішення про тариф — за Артемом; агент його не приймає й не пропонує щоразу.

### Що буває, коли кредити скінчились

Не «деплої заблоковано». Документація Netlify каже прямо: **сайти ставляться на паузу**,
відвідувачі tosho.pro бачать `Site not available`. Auto recharge у нас вимкнений, тож
єдиний запобіжник — не доводити баланс до нуля: або докупити пакет, або ввімкнути
auto recharge. Це аргумент за батчинг, сильніший за будь-яку «квоту».

### Як про це говорити

Агент **не** лякає фразою «лишилось N деплоїв із 40» — вона неправдива. Правильно:
«пуш = один деплой ≈ $0.15; накопичено N комітів — поїдуть однією ціною». Ціна
пачки не залежить від її розміру, і саме тому пачка.

## 5. Технічні запобіжники

### 5.1 Хук підтвердження пуша

`.claude/hooks/confirm-push.sh`, підключений у `.claude/settings.json` як `PreToolUse` на `Bash`
з фільтром `if: "Bash(git push *)"`.

Що робить: перехоплює будь-який `git push` і **примусово питає підтвердження**
(`permissionDecision: "ask"`), показуючи гілку, готові коміти, ціну деплою і нагадування про правила.

Окремо оброблений випадок склеєної команди `git add … && git commit … && git push`: хук спрацьовує
**до** виконання, тож комітів на цей момент ще нема і сам лише їх лічильник показав би нуль.
Тому хук читає команду зі stdin (`.tool_input.command`), помічає в ній `git commit`/`git add`
і додатково виводить стейдж, змінені файли й нові файли — щоб було видно, що саме поїде.
Довгі списки обрізаються з хвостиком «… і ще N».

**ГОЧА (спіймано 2026-08-02 у продакшн-використанні):** поле `if: "Bash(git push *)"` у
`.claude/settings.json` **не звужує виклик** — хук запускається на КОЖНІЙ Bash-команді.
А оскільки він завжди повертає `"ask"`, підтвердження почало вискакувати на все підряд
(`psql`, `ls`, `npm run lint`). Тому в самому скрипті стоїть обов'язкова перевірка:

```sh
case "$cmd" in
  *"git push"*) ;;
  *) exit 0 ;;      # не пуш — вийти мовчки, нічого не друкуючи
esac
```

Не покладатися на `if` як на єдиний фільтр. Будь-який новий хук, що повертає `ask`/`deny`,
мусить сам перевіряти команду, інакше він паралізує роботу в усіх сесіях.

Дубльовано правилом `permissions.ask: ["Bash(git push *)"]` у тому ж файлі.
Блаженний `Bash(git push *)` прибрано з `allow` у `.claude/settings.local.json` — саме він
дозволяв агенту пушити мовчки.

**Не повертати `Bash(git push *)` в `allow`.** Це знімає весь запобіжник.

### 5.2 Пропуск білду для змін, що не впливають на сайт

У `netlify.toml` є `[build] ignore` — Netlify пропускає білд, якщо пуш зачепив тільки
`docs/`, `ops/`, `*.md`, `scripts/*.sql` або `.github/` (додано 2026-08-19: конфіги
GitHub Actions і Dependabot на зібраний сайт не впливають узагалі).

Виграш невеликий (за міряний період таких комітів було 4 з 71), але безкоштовний.
Якщо в `ignore` треба додати новий шлях — додавати як `':(exclude)<шлях>'`.

### 5.3 Збираємо тільки продакшен

Перший рядок `ignore` (доданий 2026-08-19 разом із Dependabot, REQ-67):

```sh
[ -n "$CONTEXT" ] && [ "$CONTEXT" != "production" ] && exit 0
```

Документація Netlify каже однозначно: `deploy-preview` і `branch-deploy` коштують
**0 кредитів** (перевірено 29.08.2026). Тобто цей рядок нічого не економить — і нічого
не коштує. Лишаємо його не заради грошей, а тому, що PR-збірки тут не потрібні:
за останні 300 деплоїв усі 300 були `production`, тож
прев'ю нам не потрібні жодного разу, а робот оновлення залежностей відкриватиме
PR-и регулярно: без цього рядка кожен із них перетворювався б на платну збірку ще
до злиття. Перевіряє PR-и GitHub Actions, безкоштовно.

Порожній `CONTEXT` навмисно НЕ вважається приводом пропустити: якщо змінна колись
зникне, ми впадемо у звичайну логіку й зберемо, а не тихо перестанемо деплоїти.

### 5.4 PR-и від Dependabot не зливати кнопкою

Кнопка «Merge» на GitHub пушить у `main` і одразу палить деплой. Оновлення
залежностей на це не заслуговує окремих 15 кредитів. Правильно — забрати гілку
локально й повезти в загальній пачці:

```bash
git fetch origin && git merge origin/dependabot/npm_and_yarn/<гілка>
```

Робот прокидається раз на місяць, 19-го о 19:00 за Києвом.

Автозлиття (`automerge`) свідомо не вмикали: воно палило б кредити мовчки.
Виняток — PR-и `github-actions`: вони чіпають лише `.github/`, білду не спричиняють
(див. 5.2), тож їх можна зливати кнопкою не думаючи.

## 6. Що НЕ витрачає кредити

Корисно пам'ятати, щоб не боятися зайвого:

- `npm run typecheck`, `npm run lint`, `npm run build`, `npm run dev` — локально, 0.
- Коміти, гілки, `git log`, `git diff` — 0.
- **SQL-міграції в Supabase через psql** — це інша платформа, Netlify-кредитів не чіпає.
- Зміни в кронах Supabase pg_cron — деплой не потрібен.
- Правки в `docs/` — завдяки `ignore` білд не запускається.
- Правки в `.github/` (workflow, Dependabot) — те саме, білду немає.
- Прогони GitHub Actions — інша платформа, на публічному репозиторії безкоштовна.
- Відкриті PR-и від Dependabot, поки їх не злито в `main` (див. 5.3).
- **Провалений деплой** — 0 кредитів. Зламана збірка коштує часу, не грошей.
- **Відкат** на попередній production-деплой — 0 кредитів.
- Deploy Preview і branch-деплої — 0 кредитів (див. 5.3).

Витрачає кредити **тільки** успішний пуш коду, що змінює зібраний сайт або Netlify-функції.

## 7. Як перевірити залишок

```bash
npx netlify status
```

Кредити й розбивка — у Netlify UI: Team **Fayna** → Billing → Credit usage breakdown.

Порахувати деплої за період через API:

```bash
npx netlify api listSiteDeploys --data '{"site_id":"7f7dfcfc-ffcc-4702-a0e6-3a8e78bad988","per_page":100}'
```

Розбивка з UI (Billing → Credit usage breakdown) — єдине точне джерело: API кредитів
не віддає (усі `accounts/*/usage/*` дають 404, перевірено 29.08.2026).

**Auto recharge вимкнений** — це захист від несподіваного списання, але ціна захисту
висока: коли баланс дійде до нуля, Netlify **зупинить сайти**, а не просто заборонить
деплой (§4). Тому за балансом стежить людина: `916` кредитів станом на 29.08.2026,
цикл — з 27 числа.

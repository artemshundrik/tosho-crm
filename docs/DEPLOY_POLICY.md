# DEPLOY POLICY — коли пушимо і скільки це коштує

Політика викочування tosho-crm у прод. Обов'язкова до виконання для будь-якого агента
(Claude Code, Codex) і для ручної роботи.

**Головне правило одним рядком: коміт — безкоштовний, пуш — коштує грошей. Пушимо пачками, за прямою командою.**

---

## 1. Словник

| Термін | Що це | Де живе | Ціна |
|---|---|---|---|
| **Коміт** (commit) | Збережена точка в історії коду з підписом, що змінено | Тільки локальна машина | 0 |
| **Пуш** (push) | Відправка накопичених комітів на GitHub | GitHub | 0 |
| **Деплой** (deploy) | Netlify бачить пуш, збирає сайт і викладає на tosho.pro | Netlify | **≈15 кредитів** |

Ланцюжок: `коміт → коміт → коміт → ПУШ → деплой → 15 кредитів`

Ключове: **один пуш = один деплой, скільки б комітів у ньому не було.**
Двадцять фіксів однією пачкою коштують ті самі 15 кредитів, що й один.

---

## 2. Чому політика існує

Заміряно 2026-08-02 по Netlify API за біллінговий період 27.07–26.08.2026:

- **62 production-деплої за 6 днів** — усі з tosho-crm (решта 3 сайти команди Fayna: 0).
- 690 кредитів / 46 деплоїв = **рівно 15 кредитів за деплой**, плоска ставка.
- Середній білд — **74 секунди**. Тривалість на ціну не впливає.
- Деплої = **91% рахунку**. Трафік, функції й bandwidth разом — ~67 кредитів за тиждень.
- 71 коміт розтягнули на 62 окремі пуші; 15 деплоїв стартували менш ніж за 10 хв після попереднього.
- Ліміт тарифу Personal — 1000 кредитів/міс. Спалили за 6 днів.

Причина не технічна: ні build hooks, ні GitHub Actions, ні scheduled-функцій немає
(крони живуть на Supabase pg_cron і деплої не тригерять). Причина — режим «фікс → пуш → фікс → пуш».

---

## 3. Правила (жорсткі)

### 3.1 Агент НЕ пушить сам

Пуш дозволений **тільки** у двох випадках:

1. **Пряма команда Артема** в поточній розмові: «пушимо», «викочуй», «деплой», «залий у прод».
2. **Гарячий фікс**: прод зламаний, люди не можуть працювати. Тоді пушимо одразу без запиту —
   15 кредитів дешевші за простій. Про факт доповісти в тій же відповіді.

Усе інше — накопичуємо.

### 3.2 Що агент робить замість пуша

- Комітить локально стільки разів, скільки треба (безкоштовно).
- Кожен коміт — окремий і осмислений, щоб потім можна було відкотити точково.
- Верифікує **до** коміту: `npx tsc --noEmit` + `npm run lint`. Це локально й безкоштовно.
- У кінці відповіді доповідає: **«накопичено N комітів, готові до викочування»** + список.
- Далі мовчки чекає команди. Не переконує, не пушить «щоб не забути».

### 3.3 Артем дивиться зміни локально

Перевірка перед викочуванням — це `npm run dev` на localhost, не деплой у прод.
Локальний перегляд безкоштовний і необмежений. **Ніколи не деплоїмо в прод «щоб подивитись».**

### 3.4 Гілки

Працюємо прямо в `main` (див. пам'ять `feedback_ship_directly_to_main` — та частина лишається
чинною). Змінилася тільки частина про пуш: раніше пушили кожен фікс, тепер — пачками за командою.

## 4. Бюджет

Порахований з фактичного споживання:

| Стаття | На місяць |
|---|---|
| Фон (трафік, функції, bandwidth) — не регулюється | ~330 кредитів |
| Лишається на деплої | ~670 кредитів |
| **Ліміт деплоїв** | **≈40 на місяць** |

Це **приблизно 1 деплой на день**, максимум 1.5. Орієнтир — 40/міс із запасом на аварійні.

Для порівняння: темп 10 деплоїв/день = ~4500 кредитів/міс. Це не влізає навіть у Pro (3000).
Тобто перехід на дорожчий тариф проблему не вирішує — вирішує батчинг.

## 5. Технічні запобіжники

### 5.1 Хук підтвердження пуша

`.claude/hooks/confirm-push.sh`, підключений у `.claude/settings.json` як `PreToolUse` на `Bash`
з фільтром `if: "Bash(git push *)"`.

Що робить: перехоплює будь-який `git push` і **примусово питає підтвердження**
(`permissionDecision: "ask"`), показуючи гілку, готові коміти, ціну деплою і нагадування про правила.

Окремо оброблений випадок склеєної команди `git add … && git commit … && git push`: хук спрацьовує
**до** виконання, тож комітів на цей момент ще нема і сам лише їх лічильник показав би нуль.
Тому хук читає команду зі stdin (`.tool_input.command`), помічає в ній `git commit`/`git add`
і додатково виводить стейдж, змінені файли й нові файли — щоб було видно, що саме поїде.
Довгі списки обрізаються з хвостиком «… і ще N».

**ГОЧА (спіймано 2026-08-02 у продакшн-використанні):** поле `if: "Bash(git push *)"` у
`.claude/settings.json` **не звужує виклик** — хук запускається на КОЖНІЙ Bash-команді.
А оскільки він завжди повертає `"ask"`, підтвердження почало вискакувати на все підряд
(`psql`, `ls`, `npm run lint`). Тому в самому скрипті стоїть обов'язкова перевірка:

```sh
case "$cmd" in
  *"git push"*) ;;
  *) exit 0 ;;      # не пуш — вийти мовчки, нічого не друкуючи
esac
```

Не покладатися на `if` як на єдиний фільтр. Будь-який новий хук, що повертає `ask`/`deny`,
мусить сам перевіряти команду, інакше він паралізує роботу в усіх сесіях.

Дубльовано правилом `permissions.ask: ["Bash(git push *)"]` у тому ж файлі.
Блаженний `Bash(git push *)` прибрано з `allow` у `.claude/settings.local.json` — саме він
дозволяв агенту пушити мовчки.

**Не повертати `Bash(git push *)` в `allow`.** Це знімає весь запобіжник.

### 5.2 Пропуск білду для змін, що не впливають на сайт

У `netlify.toml` є `[build] ignore` — Netlify пропускає білд, якщо пуш зачепив тільки
`docs/`, `ops/`, `*.md` або `scripts/*.sql`.

Виграш невеликий (за міряний період таких комітів було 4 з 71), але безкоштовний.
Якщо в `ignore` треба додати новий шлях — додавати як `':(exclude)<шлях>'`.

## 6. Що НЕ витрачає кредити

Корисно пам'ятати, щоб не боятися зайвого:

- `npx tsc --noEmit`, `npm run lint`, `npm run build`, `npm run dev` — локально, 0.
- Коміти, гілки, `git log`, `git diff` — 0.
- **SQL-міграції в Supabase через psql** — це інша платформа, Netlify-кредитів не чіпає.
- Зміни в кронах Supabase pg_cron — деплой не потрібен.
- Правки в `docs/` — завдяки `ignore` білд не запускається.

Витрачає кредити **тільки** пуш коду, що змінює зібраний сайт або Netlify-функції.

## 7. Як перевірити залишок

```bash
npx netlify status
```

Кредити й розбивка — у Netlify UI: Team **Fayna** → Billing → Credit usage breakdown.

Порахувати деплої за період через API:

```bash
npx netlify api listSiteDeploys --data '{"site_id":"7f7dfcfc-ffcc-4702-a0e6-3a8e78bad988","per_page":100}'
```

**Auto recharge вимкнений** — коли кредити скінчаться, сайт продовжить працювати,
але задеплоїти нову версію буде неможливо до початку наступного циклу (27 числа).
Це навмисно: захист від несподіваного списання.
